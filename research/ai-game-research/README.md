# AI 遊戲研究資料庫

**最後整理：2026-10-07。**研究條件是一次使用者委託、途中無使用者干預、AI 可自主修正，最後驗收交付成品。目錄收錄不等於推薦。

## 從哪裡開始

| 需求 | 入口 |
|---|---|
| 選適合測上限的遊戲 | [候選檢閱頁](../ai-game-one-shot-review.html)、[精選候選](../ai-game-one-shot-candidates.md) |
| 查某個名稱是否已研究、曾被排除 | [可搜尋全目錄](catalog.html)、[文字全目錄](catalog.md) |
| 讀一個項目的判斷、來源及歷史 | 全目錄連到 `records/固定編號.md` |
| 查以前搜過什麼、原始描述或排除理由 | [歷史段落索引](history/index.md)，再讀相關段落 |
| 查拆分有沒有丟失資料 | [覆蓋報告](coverage-report.json)、[名稱對照](migration-name-mapping.json) |
| 接續研究 | [搜尋紀錄索引](search/index.md)與下方流程 |

## 分工與唯一內容來源

```text
精選摘要／HTML ← 人工同步推薦變更
          ↑
獨立項目紀錄 → 自動產生全目錄（HTML／Markdown／JSON）
          ↕
歷史段落與新搜尋批次（原始證據、搜尋過程、判斷變更）
```

- `records/`：一個具名遊戲、任務、基準、平台或活動一份紀錄。固定編號不隨名稱、分類或推薦狀態改變。G 是遊戲／具體題目；B 是基準；C 是作品庫／平台；E 是活動；M 是方法／鄰接研究。部分原作名稱僅是題材參照，已標示為方法參考。
- `catalog.*`：從獨立紀錄產生的目錄；不要直接編輯。它只保存查找資料，不塞入全部遊戲細節。
- `history/sections/`：93 份不可改寫的歷史段落，保留原文、日期、搜尋文字及矛盾的舊判斷；現行判斷見項目紀錄。每份不超過 16,000 bytes。原文少數本機相對連結仍以舊封存檔位置為基準。
- `search/`：未來每次搜尋一份批次檔，包含有成果、沒成果和排除項目；不再追加到同一份大台帳。目錄只留日期、題目與批次連結。單批過長則用 `-01`、`-02` 接續。
- `inventory-*.json`、遷移清單：本次盤點與追溯材料，留存但日常不需載入。原封存檔也保留作獨立備份。

## 新增一款遊戲的完整流程

1. **先查重。**查名稱、別名及 repo／作者網址，再搜尋相關歷史段落和搜尋批次。相同名稱的不同作者作品可分開登錄；同一作品換名稱或多個模型版本通常更新原紀錄。疑似相同但證據不足者先保留兩項，註明可能重複。
2. **建立搜尋批次。**記錄日期、研究問題、實際 query、查過的網址、命中編號、沒找到什麼和重查條件。無具名結果也留批次，避免重做無效搜尋。
3. **新增或更新獨立紀錄。**寫明玩法深度、完整任務、模型及工具條件、是否有人介入、可玩 build／版本、真實圖片或影片、測試證據、限制和判斷。缺資料寫「未核實」；作者自述與獨立證實分開。新資料及結論變更都回連搜尋批次；批次也回連項目。
4. **保存來源脈絡。**紀錄頂端的 `sources` 僅放已明確對應該項目的來源。`context_sources` 是歷史同一命中行的網址，可能屬於其他案例，只供查重，不當直接證據。內文連到完整來源段落。`updated` 是整理日，不是模型版本或實測日期。
5. **重新產生目錄。**由管理工具重新產生三份目錄，避免手動維護多套名單。確認新紀錄有來源與批次、連結可定位；更新搜尋索引。
6. **按影響更新摘要。**只有入選、取消推薦、證據等級或重要限制變更，才更新根目錄研究索引、精選候選與 HTML。單純搜尋線索不必進精選頁。推薦變更的原因寫回項目紀錄。

合併重複項目時保留舊編號作轉向，不刪掉它的來源與搜尋紀錄。新的候選不必有多模型比較；評選以任務深度及可檢閱證據為主。

## 到一千個項目時

仍然是一千份獨立紀錄，加上一份輕量目錄及多份搜尋批次。先以目錄定位，再讀該項目及少數證據段落；不需要一次載入一千份內文。分類、狀態及別名放在目錄欄位，避免按「推薦／排除」搬動檔案導致連結失效。

全目錄能在本機瀏覽器搜尋及篩選，無網路依賴。目錄產生時可以讀取所有紀錄的資料欄位，這是程式處理，不代表把所有內文送進 AI 上下文。跨庫搜尋也只回傳命中的段落。資料量增加後若有實際速度問題，再加入資料庫索引；現在不必先引入另一套維護負擔。

已用獨立暫存資料驗證一千筆紀錄的目錄產生、名稱衝突阻擋及下一個編號 `G1001`，並用本機瀏覽器驗證一千列的顯示與查找；測試資料沒有混入研究目錄。結果見[維護流程核對](validation/workflow-check.json)與[搜尋頁核對](validation/catalog-check.json)。這驗證文件管理流程，不代表驗證一千款真實遊戲的證據品質。

## 管理工具（供後續 AI 使用）

`tools/manage.py` 只需現有 Python，不需安裝套件。

```powershell
C:\Python313\python.exe ai-game-research/tools/manage.py lookup "Armor Alley"
C:\Python313\python.exe ai-game-research/tools/manage.py new --name "新遊戲名稱" --type game --date 2026-10-06
C:\Python313\python.exe ai-game-research/tools/manage.py rebuild
C:\Python313\python.exe ai-game-research/tools/manage.py validate
```

`new` 會查精確名稱／別名衝突、分配下一個固定編號並建立待填紀錄；仍須人工判斷同作品、完成證據及批次連結。`rebuild` 只更新目錄，不能自行決定推薦或同步精選頁。`validate` 核對歷史段落雜湊、行號連續性及盤點名稱去向；不代表驗證了遊戲品質或作者說法。`migrate` 是已執行的初次遷移，完成後禁止重複匯入。
