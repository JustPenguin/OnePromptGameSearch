# G0203 · CrossFire: Transport Ship

**使用者美術驗收（2026-10-07；[E0008](E0008.md)）：不合格。**此項只記錄美術判斷；玩法、系統、可玩程度及重跑價值另行評估。

**別名：**CF Transport Ship、穿越火線運輸船、by_opus FPS

## 任務與公開交付

作者公布的一句中文要求是「盡可能真實地還原穿越火線中的運輸船地圖，我需要一個真實的槍戰遊戲，生成一個3d頁面，盡可能發揮你的所有能力 做完之後上傳到 CDN 上 把鏈接發給我」。作者稱 Claude Opus 5.5 在 Claude Code 單次 session 內自行查地圖、做 3D 場景和槍戰玩法，再上傳 CDN；宣稱沒有人工改碼、沒有外部美術／音訊素材。原始碼、prompt 和 playable build 同時公開。

玩法含第三人稱？不，實際為第一人稱團隊死鬥：兩側出生點、V 形貨櫃與側向通道，4v4／6v6／8v8 bot、四種武器、後座與散布、換彈、瞄準、蹲跳、擊殺記錄與計分板，並有難度、日夜、畫質和 FOV 選項。原 repo 列 18 個 JS 模組、約 840 KB 單檔頁面。公開自動 QA 說明稱無頭瀏覽器模擬輸入、320 秒 soak test、獨立子代理修補 12 個邊界問題及部署前修復黑屏 bug。

[可玩版](https://claude-opus-5-5-cf-transport-ship.pages.dev/) · [原始碼、prompt、作者流程說明](https://github.com/chandan0000001/by_opus)。頁面提供實際遊玩 build；目前的紀錄尚未人工通關或對它的美術作使用者標準驗收。

## 證據界線與重跑價值

- 精確單句 prompt、可玩頁和原始碼是直接可查的；「Opus 5.5、單 session、無人工改碼、QA 時間」仍是作者在 repo 的自述，未找到原始 session transcript 或獨立重現。
- 題目有明確的對戰閉環和多人 bot 戰術、槍械手感、路徑尋敵及 3D 關卡結構，適合作為 FPS 跨系統重跑 brief。另一方面，原 prompt 只說「真實槍戰」，對武器、AI、畫面、關卡驗收沒有明確逐項規格；若模型自行補全差異大，宜預先凍結同一份 brief 和觀察 rubric。
- 成品採程序生成美術，不代表達到使用者的美術標準；目前只記為待使用者查看，不宣告通過。

## 判斷

列為**備選**：有可直接遊玩的 3D FPS、原始 prompt 和源碼，且原 prompt 夠短，適合測模型自行擴張與自我 QA；但證據大多是作者自述、題目缺少可比較的行為驗收條件，成品美術尚未由使用者檢視。它不取代高密度固定規格的 Call of Duty-style FPS brief。
