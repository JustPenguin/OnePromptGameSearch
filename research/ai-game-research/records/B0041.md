## 2026-10-07 補查：公開 testset、artifact release 與視覺評分界線（S72）

V-GameGym 已有 ACL Findings 2026 論文、[官方 GitHub](https://github.com/alibaba/SKYLENAGE-GameCodeGym)、[Hugging Face dataset](https://huggingface.co/datasets/alibabagroup/SKYLENAGE-GameCodeGym) 和[公開 leaderboard](https://v-gamegym.github.io/leaderboard.html)。官方 repo 目前包含 `generate_pygame_codes.py`、`game_evaluator.py`、`screenshot_recorder.py`，可設定 OpenAI-compatible API，生成 Pygame、執行及錄屏。HF 當前只列 `pygame_seeds_2500_filtered.jsonl`（約 25.5 MB）：單筆含 requirement、seed code、metadata 和指向 screenshot/video 的 media paths；實際 media 檔案未在 HF tree。GitHub README 宣稱包含 `gamegym_testset/files/`，但此次 main tree 實際只有程式、config 和 README，未見該目錄或 testset JSONL，故不能認定 full run artifacts 已完整公開。

paper 的流程先從 OpenCoder／The Stack v2 的既有 Pygame source 篩選，再從 code 推導 requirement、補 interactive behavior、執行驗證和人工確認，最後得 2,219 tasks／100 clusters。公開 seed row 的例子是自動播放 10 秒的 maze generator visualization，程式約 10 KB，UI 顯示 DFS 自動迷宮；這不代表多系統長流程可玩遊戲。Leaderboard 頁標示生成於 2025-10-14、72 models、GPT-5 83.25 top score，與當前最新模型不符。

視覺評分程式明確用 Qwen2.5-VL-72B-Instruct 評最多 20 張 screenshots，100 分拆成 visual completeness、UI design、functionality display、overall quality（各 25 分）；影片另評 animation、interaction、gameplay flow、dynamic quality。三軸最終採平均。這比只看 compile 有用，但 screenshot rubric 偏畫面完整、UI 和功能是否可見，沒有明確涵蓋風格一致、角色／資產設計、構圖、光照材質與動畫／特效等高階美術判準；VL judge 的 0.3 temperature 分數不是人類盲評，也不能替代本研究使用者的美術評價。它可作短 Pygame task、截圖／影片記錄流程與功能視覺／美術分離的弱 rubric 參照，不能作現行模型的 3A 遊戲案例或高上限 one-shot 主測。

此批新增 evidence 是評測方法與任務分佈界線，未新增強 one-shot 成績或顯著補強任何個別案例；S54 後第 **18** 個無強候選／無個案證據增益方向，研究繼續。
