# B0053 · Spec2Game

**類型：**基準／評測　**狀態：**可重現的規格忠實度評估參考；遊戲範圍偏小，generation 不含自主除錯迭代，官方 artifact URL 待釐清　**最後整理：**2026-10-07

**別名：**Spec2Game-Bench；GameLLM-Benchmark 是搜尋到的相近公開 repo，但未確認為論文宣稱的同一 artifact。

## 基準設計

[論文](https://arxiv.org/abs/2610.04253)於 2026-10-03 發表，研究把詳細自然語言規格轉成完整 Pygame 專案。含 15 種遊戲家族、150 個任務（每家族 1 個 canonical task 與 9 個改規則 variant）、三種 implementation complexity；遊戲類型包括 Asteroids、Space Invaders、top-down arena shooter、Mini Zelda-like room adventure、simple shop management、farming-lite 等。每個任務用七段式完整規格及可檢查功能 checkpoints。核心重點是程式能跑不代表忠實實作規則與終止條件。

Generation 固定依次產生 `state.py → game.py → rendering.py → main.py`；每一階段是分離 request、沒有共同 chat history，已產生模組鎖定供後續使用。模型生成期間不會執行候選程式或收到 evaluator/runtime 回饋，不做 semantic repair；僅允許輸出不完整或 request 失敗時以同 prompt 技術重試。因此這是受控的 staged open-loop generation，符合一次委託的一些條件，但沒有測 AI 自主 playtest 與修正能力。

評分分四軸：D1 可執行性、D2 規格實現、D3 程式品質、D4 使用者體驗／畫面與回饋；會分析 source、runtime 狀態、截圖，且部分 D2/D4 對照人工判斷。論文報告 14 個模型、3,330 個專案結果；GPT-5.6 Sol 在 Core-15 overall 67.92，Claude Sonnet 5 77.27。論文也指出 Hard tasks 整體分數較低，但整體 benchmark 仍以經典小型遊戲為主，作者明言不涵蓋更廣遊戲範圍、趣味性／新穎性／難度也未評。

## artifact 核查

論文 reproducibility statement 指向 [Aurora1094/Spec2Game-Bench](https://github.com/Aurora1094/Spec2Game-Bench)，稱內含 150 規格、pipeline、prompts、模型設定和重現腳本。但本次直接檢查該 URL 得到 HTTP 404。另找到 [Aurora1094/GameLLM-Benchmark](https://github.com/Aurora1094/GameLLM-Benchmark)，它公開 Pygame specs、prompt builder、D1–D4 評分器及 hard 的 Carrot Defense、Lode Runner-like、Farming-lite 規格；repo README 自稱是單檔 Pygame benchmark，也稱模型輸出與正式數據不隨 repo 提交。尚無直接證據證明此 fork 就是論文所稱的 Spec2Game-Bench 完整釋出版本，故兩者不合併記作已驗證的完整 artifact。

## 判斷與重查條件

保留為近期正式方法與部分任務規格來源，可借用 D1–D4 分軸、功能 checkpoints、執行證據與重複採樣設計。不是使用者要的單獨上限主題：題目大多短循環、受限 Pygame 單檔／多模組生成、無自我測試迭代。若官方 Spec2Game-Bench repo 恢復、換址或補出完整資料與 runs，重查其 hard variants 和三次採樣設計；不要把論文榜當最新模型成績。
