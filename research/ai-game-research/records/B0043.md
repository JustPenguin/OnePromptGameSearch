# B0043 · WebGameBench

**類型：**基準／評測　**狀態：**高價值閉環瀏覽器成品評測方法；全量題庫／evaluator artifact 尚未核實公開　**最後整理：**2026-10-07

**別名：**WebGame

## 任務與執行規則

[論文](https://arxiv.org/abs/2605.17637)以 111 份 frozen Structured WebGame Specification、七種遊戲類型及 D1–D4 難度標籤，測 coding agent 是否能交出使用者可操作的 browser game。每個 task／agent 僅做一次獨立 generation attempt；agent 收到相同規格、workspace、工具介面、執行預算和部署規則，產生 source、瀏覽器 URL、generation metadata 與 trajectory log。論文 trace 統計顯示，Opus 4.6 等配置平均約 20 次 agent 回合，屬單次委託下 agent 可自行運用工具的多輪流程，而非模型只輸出一段程式碼。

交件後由另一個 Codex agent 在真實瀏覽器玩測，按 spec 查互動、空間映射、規則、狀態轉換、資源／分數、勝敗條件及重開流程，再給 Excellent／Usable／Unusable 標籤；每件有一次 evaluator rollout、最多兩小時 wall-clock。主要評估器使用 Codex CLI 0.115.0、GPT-5.4-agent XHigh。主 generation roster 最新列包括 GPT-5.5 與 Claude Opus 4.7；無 GPT-6 Astra／Fable 5.1，模型結果不代表現在的最新 roster。

## 結果與價值

作者報告最佳配置 Opus 4.7 usable rate 76.9%、excellent rate 20.2%，顯示能開啟／可玩與完整滿足需求差距很大。人類複核子集 32 款，對 usable 判斷大致一致，但完全三分類一致較難。它最符合「使用者給一次任務、agent 自己建置、最後只看成品 runtime」的評測流程之一；source／trajectory 有助追溯，而獨立 evaluator 不干預 build。111 題含有一定複雜度分層，但高難 D4 task 約僅 7 題，仍偏行為密度測試，不等於長流程大作內容量上限。

## 公開材料限制

[作者研究頁](https://blog.captcha.la/research/2026-05-17-webgamebench-requirement-to-application-evaluation-for-coding-agents-via-browser)說明 111 題與執行流程；論文說明生成記錄保有 source、URL 和 trajectory。不過本次搜尋未找到作者正式連結的完整 111 題規格 repo、runtime evaluator 或可下載全部生成 builds 的入口，不能當作一般使用者已能完整重跑的題庫。獨立檢視來源與查找路徑記於 [S-20261007-40](../search/S-20261007-40-formal-generation-benchmark-audit.md)。

## 判斷與重查條件

升為高價值方法參考，能為模型比較提供「同 spec、各一個 agent run、browser runtime 成品驗收」流程。若完整 task corpus、generation/evaluator harness 與 build artifact 公開，優先抽取 D4 的高邏輯深度題，與 A2Z Big GDD 或 DEAD SIGNAL 等長流程任務互補；不單獨當使用者的完整遊戲上限主題，也不把較早模型榜說成現行結果。

## 歷史盤點摘要

111 題瀏覽器真互動分級 benchmark；過往檢索曾把它概述為「題集與 evaluator 未找到」。本輪更新為：論文詳細證實一次 generation attempt、保留來源 trajectory 與獨立 browser evaluator；但完整可重跑 artifact 仍未核實公開。
