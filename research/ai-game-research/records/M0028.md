# M0028 · Harness-of-Harness (HoH)

**類型：**自主開發方法／評測方法　**狀態：**長時程自主軟體開發的重要方法參照；具遊戲基準實驗和 Fusepoint 真實案例，並非單獨的完整遊戲 benchmark　**最後整理：**2026-10-07

## 方法概述

[論文](https://arxiv.org/abs/2609.01481) · [完整論文](https://arxiv.org/html/2609.01481) · [官方專案與遊戲展示](https://flesymeb.github.io/HarnessOfHarness/) · [公開實作 repo](https://github.com/Flesymeb/HarnessOfHarness)

HoH 把既有 coding agent 組織成連續的 Planner → Developer → QA Tester 循環：Planner 根據需求和上一輪證據制訂下一個小而可驗收的計畫；Developer 在累積中的工作區實作；獨立 Tester 運行遊戲，記錄通過與缺口。工作區與證據跨循環保留，避免每輪重頭生成。QA 回饋供後續迭代使用，不能回寫或選擇 benchmark 最終分數。

## 受控遊戲 benchmark 結果

論文在 GameCraft-Bench 的 45 題子集比較 vanilla 一輪與 HoH 三個循環。Codex CLI 0.142.5 + GPT-5.5 high 的整體平均從 49.58 升至 71.52；OpenCode 1.14.30 + DeepSeek-V4-Pro 從 26.90 升至 48.98；Pi Coding Agent 0.80.10 + MiniMax-M3 從 42.16 升至 58.78。評分是 GameCraft benchmark Overall，不是使用者的美術判定。這些 3-loop 控制實驗與 Fusepoint 70-loop case 是不同實驗，模型設定不能混為一談。

這項資料的價值在同一任務設定比較內部 QA／跨輪證據流程和既有 harness，能支持「如何建構一次使用者委託、允許 agent 自主修正」的設計；HoH 本身不提供 1000 款通用遊戲題庫或跨模型最新名次。Fusepoint 案例另見 [G0263](G0263.md)。

## 複現限制

研究頁提供 HoH-lite 的輕量版 workflow，但論文說匿名實驗包不包含 benchmark repositories/task data、raw run artifacts、analysis records、環境檔和隱藏 evaluator。Fusepoint 雖公開源碼及部分循環記錄，最初 PRD 全文與不可變的 Loop 70 build 尚未找到。要用作公平模型比較，需固定底層 agent、工具、模型版本、算力／時間限制和一則初始 brief，並由同一外部驗收者只評凍結的最終成品。
