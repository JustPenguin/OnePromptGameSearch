# B0051 · JAMER / JamBench

**類型：**基準／評測　**狀態：**高價值 Godot 專案級評測方法；可重跑題庫尚未核實釋出　**最後整理：**2026-10-07

**別名：**JamSet

## 來源與任務

[論文與附錄](https://arxiv.org/html/2606.19830)提出 JamSet 與 JamBench，從超過 240,000 個候選 repo 篩出 8,133 個經驗證的 Godot 專案，其中 300 款人工遊玩 3–5 分鐘作 benchmark；其餘 7,833 款轉成多輪訓練資料。評測含兩種不同任務：

1. 從 Game Jam 主題由零生成 Godot 專案；Task 1a 只給主題，Task 1b 額外給玩法描述。使用 50 個實際 Jam 主題，每種設定重複三次，採「先輸出專案藍圖，再依相依順序產生檔案」的 staged generation。
2. 對保留 Godot 場景的真實專案做函式、腳本或整份腳本補全；這不是完整遊戲生成。

自動驗證包含檔案完整度、Godot headless 編譯、30 秒無輸入穩定性，以及 60 秒確定性行為收集；以 L1/L2/L3a pass rate、Structural Completeness Score 和 Behavioral Alignment Score 評分。論文報告 Task 2a 從小型至大型專案的 runtime pass rate 由 80.4% 降到 5.7%，指出專案規模增加時架構與行為品質會遇到瓶頸。

## 釋出狀態與限制

論文摘要稱資料與程式公開，但正文仍寫「will publicly release」，而本次以 repo／dataset 名稱、GitHub 與 Hugging Face 來源搜尋，未找到可驗證的官方下載 repo 或任務包連結。因此目前可核實論文中的方法及數字，**不能宣稱已取得 300 題並可立即重跑**。論文測試 roster 包含 GPT-5.4、Claude Opus 4.6、Gemini 3.1 Pro 等，並非 2026-10 的最新 frontier roster。

Task 1 是題目較開放且最接近單一委託的方向，但 generation 分為多個 staged model calls，論文未證明允許 agent 執行遊戲、再依錯誤自主迭代。樣本為 2D Godot Game Jam 專案；benchmark 行為訊號不是趣味、藝術品質或一款完整長流程遊戲的全面驗收。

## 判斷與重查條件

保留為值得追蹤的 Godot 專案級生成／行為驗收方法，不列為已可重跑的高上限候選。若官方 repo、任務實體與重跑腳本釋出，優先選 Task 1 的大專案主題題，另用現行 frontier agent 自主測試修正，且保留最終交件和獨立 runtime evidence。
