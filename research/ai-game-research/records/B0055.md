# B0055 · newmodel-games: GPT-6.1 Sol vs Sonnet 5.5 matched browser-game trial

**類型：**基準／評測　**狀態：**高價值非正式同題成品組：3 份共用任務、6 個 playable source build、機械驗收及手動遊玩發現已公開；one-task feedback flow 未有原始 session 可稽核，不能作模型排名　**最後整理：**2026-10-07

**別名：**newmodel-games、新模型比べ試走、Haruka same-task game builds

## 發現與任務組

[來源 repo](https://github.com/haruka8846/newmodel-games) 及[六款 playable build 展示頁](https://haruka8846.github.io/newmodel-games/)於 2026-10-01 公開。作者標示生成日 2026-09-30：Claude Sonnet 5.5（effort xhigh，Claude Code）與 GPT-6.1 Sol（effort xhigh，Codex CLI）各從空白資料夾完成同三份任務；每個作品 N=1，未由作者手工修改。作品 source、三份逐字任務、三份 10 項 acceptance specs、grader scripts、build 截圖與可直接玩的 GitHub Pages 均在 repo。

三份共用任務為：

- [2D dungeon RPG](https://github.com/haruka8846/newmodel-games/blob/main/tasks/rpg.md)：城鎮／地城雙地圖、單格移動與牆體碰撞、隨機遭遇、回合制戰鬥、逃跑／法術／道具、經驗升級、Boss 勝利與 Game Over。需由地城探索完成完整閉環。
- [3D kart race](https://github.com/haruka8846/newmodel-games/blob/main/tasks/kart.md)：可行駛賽道、玩家與至少三名 AI 對手、三圈／倒數、方向／加速／煞車／drift、速度／順位／圈數 UI 和完賽狀態。
- [3D FPS](https://github.com/haruka8846/newmodel-games/blob/main/tasks/fps.md)：封閉場景、可移動第一人稱角色、至少四敵人接近玩家並造成傷害、武器與彈藥、HUD、逐一擊殺及勝敗閉環。

共同規格要求直接以 HTML 啟動、使用原創幾何／畫面、不得下載外部素材，並實作 `window.__game` 測試介面。RPG 和 FPS 的測試可以直接 warp／aim／refill／tick 狀態來驗證遊戲規則；Kart 測試能直接檢查狀態並操縱輸入。三類每題的自動 acceptance test 都是公開的 10 條，不是隱藏測試；題目以明確機器可讀 contract 換取高可驗收性，也會誘發對測試 hook 的適配。

## 作者報告的結果

作者 comparison page 顯示六個 build 全部通過各自 10/10 項目；本研究另獨立重現兩個 RPG build 各 10/10。其餘四個 3D build 目前只有作者頁面的成績。作者的每題 work time 及 feedback 次數仍無獨立 session／grader JSON 可覆核。

| 任務 | Claude Sonnet 5.5 | GPT-6.1 Sol | 作者補充的手動試玩觀察 |
|---|---|---|---|
| RPG | 10/10；2 次 feedback 往返；約 18 分鐘。首次 9/10，戰鬥未正確結束。 | 10/10；4 次往返；約 62 分鐘。首次 8/10，第一至三次 8/10。 | 作者稱 RPG 地城偏暗、去向不易看清。 |
| Kart | 10/10；1 次往返；約 24 分鐘。 | 10/10；1 次往返；約 38 分鐘。 | 作者稱 Sonnet 對手太弱、一路領先；Sol 左右轉向相反、預設靜音、只有單一橢圓賽道。 |
| FPS | 10/10；1 次往返；約 27 分鐘。 | 10/10；2 次往返；約 46 分鐘，首次 9/10。 | 作者稱 Sol 的敵人不會開火。此缺陷直接限制實際敵我互動，雖然 acceptance test 全過。 |

### 本研究獨立重跑（2026-10-07）

將公開 repo checkout 到暫存目錄，在 Linux／Chromium 以 repo 原版 judge `2026-09-30.1` 執行兩個 2D RPG outputs：Sonnet RPG 10/10、GPT-6.1 Sol RPG 10/10，兩者 `errors: []`。這獨立確認 RPG grader／兩個 build 在另一環境可重現。嘗試重跑 Kart/FPS 時，首次被 Chromium 對 Three.js CDN 的 `ERR_CERT_AUTHORITY_INVALID` 阻擋；加臨時 `--ignore-certificate-errors` 並改用 Linux SwiftShader 後，Chromium GPU process 在 60 秒後仍約 378% CPU、grader 無結果。為避免讓環境長時間飽和而停止；不能把 3D 首次 0/10（只因 CDN 載入失敗）或後續逾時記作遊戲失敗。repo 原 runner 強制 `--use-angle=d3d11`，與本 Linux 環境不相配；最終三維 output 的 machine results 仍只有作者報告。

以上手動觀察均為作者公開報告，非本研究實玩重現，也不是使用者美術評價。六款新 build 的美術都待使用者親自檢閱；公開 test 主要驗機制／狀態 contract，不評畫面、節奏、玩法趣味、AI 對手品質或內容充足度。

## 一次委託與公平性界線

- 作者頁稱每款只做一個 run、沒有人工修改；若自動測試失敗，會把失敗項交回模型修正，最多五次往返。這與「單一初始 brief，agent 依測試自行修復」相容，但 repo 沒有 session export 或自動編排器，無法核實回饋是否由人複製貼上、是否附加其他內容，或「各一次」是否指一次獨立起始 run 而包含多輪 user／agent 訊息。故標記為**作者申報的單一任務 run；零使用者介入未確認**，而不是單次模型 call。
- 兩個 run 用不同 coding harness、API 工具、模型工作方式；作者明確說時間不能解讀成純模型速度差。N=1 每模型／任務，沒有盲評，無法推論穩定 model ranking。
- 機器 acceptance 允許直接向 `window.__game` 操作，且只測十條預設行為；作者自己觀察到全過但玩法仍錯／缺的項目，顯示該 evaluator 不能替代正常玩家通關。
- 僅以最後 playable build 評估時，需另測全流程勝敗、AI 敵人反應、競速對手與賽道可讀性等真實遊玩品質；美術品質應由使用者分別打分。

## 現行判斷與用途

**值得納入高價值比較與重跑種子。**它是本研究近期找到最清楚的一組前沿 coding models 同題成品：任務原文、雙模型 outputs、source、machine grader、可玩頁、作者缺陷觀察俱全，三種能力面向互補。其功能分數適合作為公開規格下的機器驗收結果，不代表遊戲整體通過，也不能用來單獨比較模型。若要重跑，統一 harness 和模型可用工具，維持同一 brief，讓 agent 自主執行同一 grader；保存完整 transcript、最終 build/hash，並額外由不知道模型身份的玩家測試通關、操控與使用者美術偏好。
