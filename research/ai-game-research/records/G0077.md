## 任務與測試範圍

BitsMinds 以單一 brief 要求重製 Hill Climb Racing，輸出單檔、自包含 HTML；不得使用 CDN、網路請求、圖片或 web font，全部美術以程式繪製，頁面須能在只允許 scripts 的 sandbox iframe 執行且不使用 local storage／cookies。任務要求開場、選單和單關遊戲形成可返回的流程、雙輪懸吊車輛與起伏地形、追蹤鏡頭、鍵盤／觸控油門煞車、車輪貼地及越坡離地、空中翻覆、失敗、免重載重開、HUD、結算和不依賴畫面更新率的物理。原 brief 沒有要求燃料或金幣；作者觀察各模型都自行加入了其中某種收集系統。

## GPT-6.1 Sol｜Ridge Run

[作者完整 hands-on 報告](https://www.bitsminds.com/news/claude-opus-5-5-vs-gpt-6-1-sol-hill-climb-2026) · [直接玩交付 build](https://www.bitsminds.com/buildoff-2026-09/hillclimb_sol61.html) · [作者保存的實際遊戲畫面](https://www.bitsminds.com/buildoff-2026-09/hillclimb_sol61_play.jpg)

作者稱模型在 2026-09-30 以 Codex CLI `max` 完成，耗時 57 分 38 秒。文章表示每個模型只有一次嘗試、沒有 follow-up 或交件清理，兩個檔案直接以原樣嵌入頁面；Sol 收到 9 月 23 日給 Opus 的同一 brief，除輸出資料夾／檔名外逐行相同。原始 prompt 檔與完整 session 沒有公開，故這些流程仍屬作者報告，未能由第三方 trace 獨立稽核。Sol 開始寫碼前讀取了 Codex 過往 one-shot 的持久記憶；作者稱其中沒有此 Hill Climb 題的資訊。工具包括 shell、Node 與 browser；`max` 未啟用 `ultra` 的自動任務委派。

交付為約 58 KB、194 行的單檔 build。單一賽道約 900 公尺、五個命名路段、爬升 76 公尺，含選單、結算、鍵盤／觸控、懸吊、翻車、重開、HUD 和音訊。作者 hands-on 量測並讀取遊戲狀態：全油門在 378 公尺翻車；維持 60 km/h 在 594 公尺翻車；30、40、50 km/h 可於約 81–115 秒完賽。80 枚金幣分成 20 組，每組 4 枚，作者所測每個完賽 run 都收齊；五桶燃料各加 42%，滿油全油門約 80 秒，而其完賽 run 結束時燃量至少 76%。低速在陡坡停住後持續耗油，8、12、20 km/h 的幾次測試會耗盡燃料。報告亦描述固定 120 Hz 步進、懸吊位移、空中控制、重開、多點觸控、sandbox iframe 與不同 frame rate 的測試，並稱提交前留有約兩打截圖和自動化測試資料。

BitsMinds 的主觀評分是 graphics 3/5、physics 4/5、sound 3/5、gameplay 3/5，合計 13/20。作者認為物理穩定但金幣及油耗太容易，駕駛策略對完賽影響有限。這是單一作者操作 build 後的評分與程式狀態量測，不是盲測或自動 evaluator；畫面分數也不代替使用者的美術驗收。使用者已判定 Ridge Run 美術不合格（2026-10-07；見 E0008）。

## Claude Opus 5.5｜Hill Hopper 對照

[直接玩 Opus build](https://www.bitsminds.com/buildoff-2026-09/hillclimb_opus55.html) · [作者保存的實際遊戲畫面](https://www.bitsminds.com/buildoff-2026-09/hillclimb_opus55_play.jpg)

Opus 5.5 的 build 於 2026-09-23 生成，約 98 分 6 秒，9 月 30 日文章沿用既有檔，沒有重跑。作者給 graphics 5/5、physics 5/5、sound 4/5、gameplay 5/5，合計 19/20。其九段路線、燃料限制及空中金幣要求更多駕駛選擇。它使用 Claude Code subagent、maximum effort；任務記憶也提供給子代理，harness 與 Sol 不同。因此 13/20 對 19/20 是作者的非盲同題產品比較，不能當純模型因果排名。

## 證據界線與用途

文章描述了任務全文的實質條件、單次委託規則、工具和多項 build 上的量化測試，兩個未清理 playable 檔和實際輸出圖可直接檢查。它比只有作品集宣稱的單次 run 有更具體的可核對材料；但原始 prompt、完整 agent session 和獨立重跑皆未提供。GPT-6.1 Sol 與先前 GPT-6 Astra build 有相同 layout 與部分物理常數；作者認為可能來自模型家族共享訓練內容，這是作者推論，不是已證實的來源因果。

本題可測固定任務下的車輛物理、狀態閉環、簡短遊戲操作和 agent 自主 QA，適合新模型重跑或技術副測。只有單一長關及少數系統，不能代表多系統大型遊戲的整體上限。美術（使用者判定不合格）、可玩性、內容完整度、one-brief 條件和證據強度分開評估。
