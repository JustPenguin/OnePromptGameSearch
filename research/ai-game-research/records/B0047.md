# B0047 · GameForge Harness

**類型：**基準／評測方法　**狀態：**方法參考；有獨立驗收與可重跑證據，但 Open20 任務偏小且執行器目前偏 OpenAI　**最後整理：**2026-10-07

**別名：**GameForge-Harness、AlbusChen/GameForge-Harness

## 為何值得保留

GameForge 將「一次交辦後由模型自行完成」與「由另一個評測器驗收」分開。README 說模型在 disposable workspace 中可自行檢查檔案、編寫工具、呼叫原生引擎、截圖並依執行回饋調整；完成後，solver 看不到的 evaluator 才負責建置、啟動、輸入回放、記錄及核對。它明示不強制工具順序、不插入 harness 自動修復，也不把中間驗收資料回饋給 solver，與「AI 可自行修正、使用者不介入、只驗收最後交付物」的流程相當接近。

官方公開兩種可重跑材料：

- **Godot Open20：**20 個空白 Godot 專案中的創作 brief，涵蓋 survival、platformer、puzzle、strategy、simulation、racing、rhythm、combat、sandbox 及 local co-op。凍結 manifest 指定 GPT-5.6 Sol medium、每題一次、900 秒、Godot 4.4.1、無網路、無中間 harness 驗證、無自動修復。它包含可重用的固定 brief 與評測 protocol。
- **GameCraft-Bench Full140 重跑：**GPT-5.6 Sol high、140 個公開 Godot 任務各一個 open solver session；作者報告 140/140 build、732/732 官方互動回放，沒有 harness repair pass。作者明確將 63.15% 標為透過 Codex subscription transport 得到的 judge approximation，而非可直接與官方 leaderboard 等同的分數。

## 對本研究的適用邊界

- Open20 每題都明確要求「compact」小型遊戲，設計目標是跨 20 種機制做配對比較，論文本身也說這不是自然使用者需求的分布。因此它**不應被推薦為測遊戲上限的單一高難題**；可借用的是單次 open solver、凍結空白工作區、外部輸入回放與盲評方法。
- 較有上限價值的是將同一 harness 用於既有完整 GameCraft-Bench 任務庫；但公開 140 題仍以 2D Godot 為範圍，不涵蓋 3D、多人網路、長期製作流程或主觀「好不好玩」。應與較開放的 3D／長流程題搭配，而非取代它們。
- 報告、分數及 replays 由專案作者發布；獨立性是 harness 架構上的 evaluator 隔離，不代表第三方已重做全部實驗。Open20 每題僅一次，品質評審模型與 solver 同屬 GPT-5.6 家族；遊戲完成度／好玩程度仍需使用者驗收。
- 目前 README 列出的 solver 路徑為 Codex subscription 與 OpenAI Responses API。對跨廠商比較，須先確認 Anthropic 等其他 provider 可否以相同工具與預算接入；不能假設現成支援。
- 已公開成績的 solver 為 GPT-5.6 Sol，日期 2026-08-24／28；對當前前沿比較而言，應把它視為**可供最新模型重跑的評測方法與任務環境**，不把舊 roster 說成最新模型榜。

## 建議用法

如果採用 GameCraft-Bench 做高系統重跑，固定公開原始 task、Godot 版本、資產庫、可用工具、model effort、時間／token 上限及嘗試次數。讓 solver 在一則任務內自行驗證；完成後一次性執行獨立建置／輸入回放與記錄，再由使用者單獨評遊玩和美術。不要把 Open20 的小題結果混進高上限主測，也不要將 GameForge 自報分數當作獨立官方分數。
