## 推薦用法：採用公開完整任務，將舊作只當參照

[BridgeBench 完整任務](https://www.bridgebench.ai/prompts/30220eea-7128-4a4f-abb6-eba65412eb68) · [作者 Opus 5.5 repo](https://github.com/bridge-mind/claude-opus-5.5-zombies-game) · [作品收錄及限制說明](https://aiidelist.com/blog/opus-5-5-dead-signal)

BridgeBench 頁面於 **2026-09-04** 提交了一份約 438 行／19,740 字的 Three.js、TypeScript、Vite 任務，直接要求一個使用者 prompt 後，由 agent 自主規劃、實作、執行、檢視、測試、修正與潤飾。它明確禁止只交腳手架、標題畫面、漂亮場景或最低限度射擊 demo；要求可離線遊玩的單人完整撤離任務，約 8–10 分鐘，有三個威脅區、守點與狩獵合約、探索／拾荒、槍械／彈藥／裝甲／升級、殭屍尋路和行為狀態、污染倒數、呼叫直升機、守住最後一波、登機勝利／死亡或逾時失敗，以及可重開的結果流程。

它也把常見假完成情形寫成可驗收條件：牆體要擋子彈與敵人攻擊；獎勵只能領一次；槍械狀態／彈藥不可重複；導航需避障；地圖顯示真實位置；提取必須按順序且玩家到場互動；測試需玩實際本機 build、看畫面／console 並修 bug。視覺則要求原創工業隔離區、近景武器、可辨識感染者、可進入建築、環境敘事和材質細節。**這是研究方核對過的重跑 brief，並不宣稱它等於下述作者成品使用的原始 prompt。**

Claude Opus 5.5 的 Dead Signal repo 提供源碼、README 和測試；未找到可穩定確認載入的作者官方 playable build，第三方鏡像[曾回報載入失敗](https://www.igrasu.ru/en/games/A-D/D/dead-signal)。**新查到同一作者 BridgeMind 於 2026-09-28 發布 Sonnet 5.5 的同名／相近玩法 source build**：[G0236](G0236.md)。該 repo 可本機 `pnpm dev` 運行，README 也稱由 single prompt 和 subagents 製作，但沒有作者原始 prompt、session trace、frozen hash 或 run logs；不能確定它是否採用 BridgeBench 438 行 brief，也不能把 Sonnet source 當成該 438 行題目的 run。Build 可追查性比前次盤點增加，但一次委託流程仍主要是作者申報。詳見 [S22](../search/S-20261006-22-frontier-game-benchmarks-and-latest-builds.md)。

## 判斷與重查條件

此 brief 對一次委託中的自主 QA／修正特別適配，並把核心遊戲循環、任務完成和視覺驗收都明確定義；比只要求「做一款 COD」的短題更能分辨功能是否真的完成。代價是規格很長且細節多，部分設計空間被限制；它測的是依複雜規格完成和自我驗收的上限，不是從零自由創作。**仍是系統整合與自我修正主測強候選。**新找到的 Sonnet build 是相近作品、非已證明的同規格 run；實際比較應將原始 438 行 brief 原樣交給當前模型，各自從空 workspace 完成及自主 QA，再只評該 run 的凍結交件。
