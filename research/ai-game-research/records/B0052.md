# B0052 · A2Z GameSpec-Bench

**類型：**基準／評測　**狀態：**強追蹤候選。官方頁提供 100 題模型結果、方法與額外 GPT-6 Astra 3D gameplay captures；完整 100 題 GDD、contracts、source build 和 evaluator 尚未可下載，不能立即完整重跑　**最後整理：**2026-10-07

**別名：**A2Z GameSpec Bench、KRAFTON GameSpec-Bench

## 來源與任務規模

- 2026-09-30 發表論文：[arXiv 摘要](https://arxiv.org/abs/2609.39564)及[完整論文](https://arxiv.org/html/2609.39564)；[KRAFTON 官方 GitHub repo](https://github.com/krafton-ai/a2z-gamespec-bench)；[官方專案頁](https://a2z-gamespec-bench.github.io/)。
- 100 份長篇 GDD：50 Small、50 Big。Big 平均約 26,297 tokens、每份平均 84 項結果要求，設計範圍是相互影響的系統、戰役、經濟與敘事；類型包括 simulation/management、platformer/metroidvania、adventure/narrative、strategy、action roguelite/survival、RPG、shooter/bullet hell、sports/racing 等。論文的比較表列 GDD 平均長度 20,191 tokens。
- 主要環境為 Phaser 4.1、TypeScript、Vite 的 2D 單人 browser game；各 coding agent 從相同 starter project 與 runtime interface 開始，交付 source project 和可執行 web build。論文另以 GPT-6 Astra 建置三款 Three.js 3D 案例（Sonic: Cascade Coast、Diablo Cathedral、Rocket League），提供評分與部分截圖／行為證據，並非 100 題 3D 版本。
- 固定的 Dependency-Aware Contract 由 GDD 轉出規則、限制與前置相依關係，初始建置時不提供給建置 agent。測試由 source-code inspection、scenario-based replay、adaptive playtesting 三軸組成；adaptive tester 會由遊戲狀態決定下一步，另可將遊戲初始化到規則前置狀態來測未觸發條件。三軸等權形成 GDD Fidelity，並保留逐規則證據。

## 最新模型實測與自主修正

論文的九種 coding-agent 設定均覆蓋 100 題、每題獨立產生三個 build，並由 evaluator 對每個 build 各判三次。公開 roster 包含 Claude Fable 5.1、Opus 5、Opus 4.8、GPT-6 Astra、GPT-5.6 Sol、GPT-5.5、Kimi K2.7、GLM-5.3、DeepSeek V4 Pro；截至本次檢閱，這是高規格遊戲生成研究中包含 GPT-6 Astra 的近期一組實測，但不等於 2026-10 最新型號全覆蓋。

論文報告 overall GDD Fidelity：Fable 5.1 77.0、Opus 5 73.9、GPT-6 Astra 71.6；Big split 分別 71.1、66.8、64.6。高 compile/runtime verifiability 不等於需求忠實度。對 50 個 Big GDD 的控制實驗中，同一 GPT-5.6 Sol 初始 build、同一 revision agent 做兩輪修正；提供 source+replay+playtest 的 requirement-specific evidence 後平均得 74.3，高於只看 GDD/source 的 self-revision 67.0（作者報告相對提升 10.9%）。這證明評測回饋能協助 agent 自主返工，但不能誤說所有排行榜分數都來自多輪迭代，也不能把 evaluator 回饋當作完全無人介入的一次基準結果。

## 釋出狀態複核

截至 2026-10-07，官方 GitHub [`main` README](https://github.com/krafton-ai/a2z-gamespec-bench)仍將 Code & Data 標為 coming soon；repo 的 tree 有 README、MIT license 和約 16 張展示圖片，沒有 100 份 GDD、Contracts、scenario test corpus、generation source projects 或 evaluator/harness。arXiv HTML 的「code and datasets are available」指回 project page，但 project page 的 Code link 又指 GitHub，頁面本身沒有可下載資料包，因此目前仍不能照原論文完整重跑。

另查 [KRAFTON Hugging Face dataset](https://huggingface.co/datasets/KRAFTON/A2Z-GameSpec-Bench)：API tree 只有 `.gitattributes` 與 21-byte README，dataset viewer 顯示 dataset empty，未發布資料。官方頁和 paper 可看部分方法、榜單、GDD 節錄與選定輸出畫面，但不等於完整 benchmark release。

## 對使用者目標的判斷

這是目前最值得優先追查及重跑的正式 benchmark 種子：長 GDD、明確的跨系統規格、能要求 agent 自行 playtest／修正、最後以 playable build 的規格落實度評分，Big split 顯示難度確實高。若日後只選一個高上限規格，宜優先看 Big split 的管理模擬、冒險或 RPG，而不是 Small split 的單屏反應／記憶小遊戲。

但不能把 A2Z 目前的展示頁等同完整可重現任務庫。GitHub README 仍寫「Code and dataset will be available soon」，repo 未放 100 GDD、contracts、runtime evaluator 或 generation harness；Hugging Face dataset repository 目前為空。現在可核實規格家族、官方榜單、evaluation setup、若干 GDD 節錄與三個 GPT-6 Astra 3D extension 的部分 gameplay frames／scores，但不能下載完整 corpus、取得所有 playable builds、查各 build 的 session，或自行完整重跑。生成過程精確 user/agent transcript、各模型使用同一任務上下文的 session 證據亦未公開。

## 納入狀態與重查條件

納入強候選追蹤，不因完整任務庫未釋出而排除：長規格、跨軸 evaluator、現行 GPT-6 Astra／Fable 5.1 模型結果和 3D output frames 都有實質價值，並且符合「agent 自主建置、QA／評估、最後看 build」研究方向。現階段仍不將 benchmark 宣稱為已驗證一則 user task/no-human-intervention 成績，也不列作可立即完整重跑題庫。當官方釋出完整 GDD、固定 contracts、可執行 harness 與 build/session artifacts 後，先核 Big GDD 授權及實際 build，再挑題以現行模型跑一次 user task；記錄首次 brief、agent 自主迭代 trace、凍結 build、分軸評分與使用者美術評價。新補的 3D captures 可供使用者先行 art review，個案見 [G0283–G0285](G0283.md)。搜尋及 release audit 見 [S76](../search/S-20261007-76-a2z-gamespec-bench-artifacts-and-release-audit.md)。
