# G0268 · 夜巡录：荒庙篇 / Night Patrol: Abandoned Temple Chapter

**類型：**遊戲／具體作品　**狀態：**完整第一幕牌組 roguelike 切片；Codex 多輪人機協作成果，不符合零 follow-up 一次委託；高價值重跑任務線索　**最後整理：**2026-10-07

**美術：待使用者評價。**作者提到 GPT-Image 2.0 及素材包，但本研究未代使用者判定成品畫面品質。

## 作品、任務與可核實證據

[作者的 [X 原始長文](https://x.com/op7418/status/2050023375746285747)與[素材工作流貼文](https://x.com/op7418/status/2050030364018819581)是第一手敘述，後由 [Toolin 報導](https://toolin.ai/blog/codex-build-complete-game-in-one-afternoon)轉載整理。作者說最初只用約七字向 Codex 問能否做類似《殺戮尖塔》的遊戲，第一個 demo 後又要求用內建 GPT-Image 2.0 產生遊戲素材；另有從上千張圖的素材包中搜尋挑選、角色動畫／打包等後續工作。這表示 AI 在任務範圍內有很強的工具規劃能力，但不能把「一句 kickoff」描述成整個最終遊戲只收到一則使用者指示。作者稱整個下午完成，並說約三小時出現首個 playable prototype；文章和 X 長文都沒列出 Codex 模型 ID／版本、精確初始文字、每次後續指示逐字稿或 build 冻結時間。

[公開 GitHub repo](https://github.com/op7418/Night-Patrol)的 README 將遊戲稱作一個完整的第一幕 demo，並記錄歸藏 × Codex 協作；repo API 所示建立於 2026-04-30、最後 push 約 2026-05-01，後續有更新。其 [planning 文件](https://github.com/op7418/Night-Patrol/blob/main/docs/PLANNING.md)規劃約 15–25 分鐘流程、一名可玩角色、約 20 張卡、符印／香火／連攜、地圖事件與商店、普通／精英／Boss 戰及程序音訊；[first-act roadmap](https://github.com/op7418/Night-Patrol/blob/main/docs/FIRST_ACT_DEMO_ROADMAP.md)與[實作說明](https://github.com/op7418/Night-Patrol/blob/main/docs/IMPLEMENTATION_DETAILS.md)記錄後續迭代、缺漏及打磨。這些文件代表設計／實作範圍，不應一概當作目前 build 已完整實現。

[GitHub 公開 [commit history](https://github.com/op7418/Night-Patrol/commits/main)顯示 2026-04-30 的「Initial playable night patrol prototype」之後，同一日持續加入勝利過場、生成敵人立繪、戰鬥音效／cinematic、難度選擇與畫面／HUD 打磨，再打包 v0.2.1-demo。commit timestamps 與作者所述「首個 prototype 之後接著完善」相符；它無法告訴我們每個提交是 agent 自主規劃還是何時收到哪一條人工要求，但可直接確認 release 與最初 prototype 不是同一個 frozen state。作者並未標 Codex 型號／版本或公開 session。

| 面向 | 判斷 |

| 美術 | 待使用者評價；作者稱使用 GPT-Image 2.0，並混用另行取得的素材，不據此推斷成品是否合格。|

| 證據強度 | source、版本 release、規劃與實作文件可直接查閱；開發敘述與耗時是作者自述；無 frozen initial/final diff、session transcript、精確模型版本或獨立 QA。|

保留理由不是把多輪成果冒充一次交付，而是它提供可重跑的中高系統任務、可下載 demo 和透明規劃文件，可供新模型在 frozen prompt／空白工作區下重新測試。若作者公開逐字 kickoff、每次人類介入及 build 時間線，或出現新模型從原 brief 一次完成相同範圍的 build，再重開嚴格條件判定；在此之前只作多輪方法／任務參照，不列精選 one-shot 成績。
