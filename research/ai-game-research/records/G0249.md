# G0249 · Flightsim (Goldie Bench one-shot task)

**類型：**遊戲／具體題目　**狀態：**副題／視覺與飛行物理校準參照；不列上限主測（循環窄、無自主修正、未含最新模型）　**最後整理：**2026-10-07

**別名：**Flight Simulator — take off, fly over terrain, full flight HUD, land on the runway

## 任務與公開 run

Goldie Bench 的 [Flightsim 任務頁](https://goldiebench.com/tasks/flightsim)公布一則短 prompt：「Flight Simulator — take off, fly over terrain, full flight HUD, land on the runway.」並要求各模型交單一 HTML；頁面明言沒有 iteration 或 prompt example。作者列 28 次嘗試、23 份有分、均分 7.61／10，並連到每個實際 one-shot HTML。這是可以直接觀察多個首次生成 build 的視覺／物理校準資料，不是 28 個對自主修正能力的測試。

頁面列出的模型包括 Fable 5、Opus 5／5.5、GPT-5.6 Sol、Grok 4.7、MiMo V2.6 Pro 等；未見 GPT-6 Astra 或 GPT-6.1 Sol。作者稱 Fusion 第一（8.7），但該配置標註 `showcase · game-director`，其基礎模型組成、prompt 設定和 agentOS 內部工具不透明；分數是作者 eyeball 評估並引述 source comparison guides，不是盲評／統一遊玩測試。

## 難度價值與限制

每個 build 都能開啟遊玩，可看到飛機模型、機場、HUD、飛行和部分 landing loop；頁面另列各模型優缺點。作者文字稱 top entries 有地形／機場、HUD，部分試玩可核對速度與高度會變化。這比純靜態 3D 作品更能檢查 flight controls、flight state 與視覺呈現。但題目主要是一個環繞機場、起飛與降落的短循環，不含長程關卡、角色成長、經濟或內容生成；no-iteration protocol 也取消了使用者希望允許的自主 playtest／修正。當前 frontier 模型未進 roster，頁面／跑次時間未給出完整可重現的模型與系統設定，分數的盲性也不足。

## 判斷

保留作**視覺／飛行物理副題和比較範例**，不列為一次生成完整遊戲的上限主測，也不把作者 8.7 分或展示清單當客觀模型排名。若把它交給現行模型做副題，應允許 agent 在一次任務內自我測試與修正；另用獨立 playtest 驗證真實 takeoff／landing，再把視覺分數與操作成功分開記錄。只有當 bench 加入最新模型、公開模型與 harness 確切版本／執行日期、或擴充為多個任務階段時再重核。搜尋過程見[批次 S34](../search/S-20261007-34-astraflight-prompts-and-artifacts.md)。
