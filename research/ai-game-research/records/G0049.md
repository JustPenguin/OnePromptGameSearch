# G0049 · Diablo-style ARPG

**類型：**遊戲／具體題目　**狀態：**推薦作共同重跑題　**最後整理：**2026-10-06

**使用者美術驗收（2026-10-07；[E0008](E0008.md)）：不合格。**此項只記錄美術判斷；玩法、系統、可玩程度及重跑價值另行評估。

**別名：**AI for Mortals Diablo ARPG、Diablo系統題

## 為何重排為優先重跑候選

這不是只有角色移動與打怪的短 demo 題。它把城鎮、至少四層隨機地城、探索迷霧、角色升級、技能資源、五種敵人行為、精英與多階段 Boss、裝備掉落、背包、商店、死亡懲罰、存檔及完整勝利流程都放在同一款遊戲裡；還要求模型用自動化從城鎮一路打敗 Boss、修好阻塞問題，並調到熟悉類型的玩家可在 15–30 分鐘通關。這種規格同時壓玩法、系統連動、平衡、長程狀態與自主 QA。

## 公開任務與執行證據

- **精確任務：**作者公開逐字 prompt，要求瀏覽器可玩、斜角即時戰鬥、滑鼠移動／攻擊、至少四技能、程序地城、不同敵人、隨深度變化的裝備詞綴、存檔與原創美術音訊；最終需 AI 自己自動通關並確認無 console error。完整規格見[任務頁](https://www.aiformortals.co/built-by-pat/build-a-diablo-style-action-rpg-5koom8)。
- **公開 build：**頁面列出 Opus 5.5、Fable 5.1、GPT-6 Astra 與 Sonnet 5.5 等 model cards，展示實際 build 截圖。模型／耗時／token／成本表顯示 Opus 5.5 約 53 分鐘、Fable 5.1 約 52 分鐘、GPT-6 Astra 約 36 分鐘；Sonnet 5.5 約 81 分鐘。不同 run 的數字是作者文章紀錄，不代表獨立測量。
- **自主流程可信度：**作者文章確認主要 runs 使用同一份 prompt、各家原生 coding agent、high reasoning 與 goal mode；goal mode 讓 agent 持續工作直到任務內的完成條件。可是文章明確說 Diablo 建置屬於較早一輪、未納入本次正式影片，也沒有像後續 Backrooms 測試那樣明確聲明零追問且不重跑。因此，公開材料足以把它列為高價值重跑題，但「原 run 嚴格無追問、原始交付已凍結」仍待核實。
- **可檢閱限制：**公開 build 頁標示 Sonnet 5.5 成品是 native app、沒有 web version。找到的是實際 build 截圖，不是可供使用者直接遊玩的瀏覽器成品；其他三版亦未在此頁提供清楚可開啟的 playable demo。不得把截圖描述成可玩連結。
- **美術：**任務允許程序圖像、自製 sprite 或 3D，但目前沒有由使用者確認的視覺驗收。截圖只供查看真實生成畫面，不代表已達使用者門檻。

## 評測使用建議

它最適合當**同一規格重跑題**：將公開 prompt 交給當下最新的 coding agent，各一個新工作階段，允許 agent 自行規劃、開發、玩測、除錯與修改；結束時保存完整 session、停止時 source/build、測試報告與模型自述的未完成項。由使用者只檢查最終凍結 build。跨模型比較不是題目成立的必要條件，而是此題具備的附加參照。

如果不想指定 browser-only output，重跑時可清楚定義可交付 build 格式；但各模型必須收到同一規則。建議驗收至少實際跑完整個四層到 Boss 的閉環，另用不同 seed、死亡後返回、存檔重載、技能消耗、掉落詞綴和商店買賣檢查功能是否真實連動。高系統範圍仍可能在畫面、操作或平衡上失敗，所以不能預先當作美術通過。
