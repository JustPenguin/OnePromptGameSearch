# B0057 · Code Bench Fun

**類型：**基準／評測　**狀態：**可重現的一次 completion 多模型建置與成本／tokens／延遲展示工具；現行樣本為自動播放 2D physics toy 而非完整互動遊戲，評審依 source code 而非實際畫面，僅作 one-shot 方法與視覺 prompt 參考，不列完整遊戲候選　**最後整理：**2026-10-07

## 方法與可查資料

GitHub Pages 提供 [live site](https://ggcryptoh.github.io/code_bench_fun/)、[Cars vs Canyon build race](https://ggcryptoh.github.io/code_bench_fun/run.html?id=cars-vs-canyon)、[One-Shot Bench](https://ggcryptoh.github.io/code_bench_fun/bench.html) 和每模型獨立遊戲 HTML。repo 保存所有跑分 JSON、generated game files 與 zero-dependency Node runner。Cars vs Canyon JSON 的 prompt、shared system prompt 與六模型結果均可直接檢閱；建立時間為 2026-07-05。

「Cars vs Canyon」原始 task：

> A 2D side-view physics simulation: a red car and a blue car race in from the left, hit launch ramps and jump across a deep canyon side by side. Suspension compression and bounce on landing, kicked-up dust and debris particles, parallax sky with drifting clouds and a warm sun. After each jump the cars reset and run again with slightly different speeds, forever. Fixed camera, no user input, pure autoplaying simulation.

共用 system prompt 要求 one-shot、單份 self-contained HTML、不得使用外部資源，並明說 simulation 自動運行、視覺需有 polish，方便在 screen recording 上觀看。各 build JSON 列一個 turn。樣本 model ID／provider 記載 Fable 5 (`claude-fable-5`)、GLM 5.2、GPT-5.5、Opus 4.8、Grok 4.20、Gemini 3.5 Flash。公開列表中五個 build 成功返回 HTML、GLM row 失敗為 no HTML；GPT、Fable、Opus 與 Grok 各一回合，Gemini 一回合；所有數字均為作者的 runner 紀錄。

## 評分與限制

- repo 自述 judge 為 Opus 4.8；分數維度為 works／fidelity／polish／creativity，權重 35／30／25／10。Cars vs Canyon row 的結果為 Fable 5 9.2、Opus 4.8 9.2、GPT-5.5 8.5、Grok 4.20 5.3、Gemini 3.5 Flash 2.0、GLM 5.2 失敗。
- 判分依模型輸出的 source code，未顯示人類實際玩 build 的盲測流程或 screenshot vision scoring。故 `polish` 不等於玩家對美術或畫面的評價，不能用作使用者美術驗收。
- task 是無輸入的 2D 自動物理模擬，沒有玩家目標／操作／關卡或勝敗循環，遠低於完整遊戲上限題型。使用者未再輸入並非難點，評量的是受限一回合程式輸出。
- README 宣稱每模型 no retries，但 runner 文件也說會對 truncated HTML 做一次自動 retry；與純粹無重試規則有邊界差異。Cars vs Canyon JSON 顯示每列 `turns:1`，但仍應讓 benchmark 在未來重跑時明確保存 retry 次數和實際底層呼叫。
- 當前固定資料只有兩個 run，最具代表性的 Cars vs Canyon 日期為 2026-07-05；模型不是目前最新前沿版本，不列當前能力排名。

## 定位

值得保留作為一次 completion 的成本／token／耗時透明展示、保留失敗列和 visually-polished prompt 樣板；不能代表 AI 在單次任務後完成玩家可玩的完整遊戲。可將其輸出協定延伸至高系統任務，但應加入 real gameplay verification、玩家美術盲評與無重試 trace。
